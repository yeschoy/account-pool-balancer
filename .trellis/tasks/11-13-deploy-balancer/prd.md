# Deploy 独立号池管理与推理接入

## 目标
在独立分支 `feat/deploy-balancer` 中接入 deploy.com，复用现有 OpenDesign 管理台与调度器，提供账号管理、概览、路由、错误和重试规则，不干扰其他池。

## 已确认事实与边界
- 用户要求实现独立分支，并提供一把 Key 用于连通性和小额真实推理测试；真实凭据不进入源码、日志、Git 或任务记录。
- 基线 `9410a52`。原 master 的 Deploy 注册机/Mistral 等未提交代码不迁移；注册链路调研仅作参考。本次管理现有 API Key，自动注册、创建/删除上游 Key、绑卡、充值与部署不在范围。
- 仓库调研记录给出 API 根 `https://api.deploy.com/api/v1`，Bearer 使用 secret 而非 access_key；目录成功不证明 Key 已激活或推理授权。
- 已记录模型 `deepseek-ai/deepseek-v4.1-flash-1017`、`zai-org/glm-5.3-flash`。模型支持以实时目录和推理结果为准。
- 按 `.trellis/spec/backend/provider-onboarding.md` 验收。上游不可由当前凭据获取的余额/协议必须明确说明，不伪造或硬编码为零。

## 要求
R1 独立 provider/group/client/import Key；账号 CRUD、批量导入与重复处理，支持启停、代理、权重、优先级、并发和 RPM。
R2 仅接入有证据的 Chat Completions 与模型目录；保留原始请求体/模型/工具/推理字段和流式结果，不擅自转换其他协议。目录同步落盘，来源变化/迟到结果不得污染新来源。
R3 独立可持久化路由、轮询、模型缓存、健康、会话/TTL、超时、等待及尝试上限；不展示 Deploy 无效的钱包/套餐路由参数。日志保留等共享设施需显式标注且本池保存不更改其他池配置；价格表按官方价格独立保存，不影响其他池。
R4 独立错误/重试默认值及完整可视编辑；明确区分 401、403、402、429、5xx、网络错误。保留输出后不重放等安全门，规则真实参与运行。
R5 概览显示本池账号状态、请求、成功率、Token、估算费用、缓存观测、会话、模型与出口；余额无可靠来源时显示未知及原因，不能把目录当成额度或授权。
R6 只读检测与真实推理测试分别说明；默认模型正确，允许手填；小 token 上限产生 reasoning/空 content 不误判为连接失败。
R7 测试覆盖保存/重载、Mock 错误路径、来源变化、跨池隔离、真实本地浏览器后置条件与用户授权的真实推理。

## 验收
- A1(R1): 账号/客户端/导入凭据仅流向 Deploy；重复导入与错误 provider 均有可解释结果。
- A2(R2,R6): Mock 与真实 Key 分别验证目录和 Chat，流式/非流式不丢字段；不支持路径本地拒绝且不请求上游。
- A3(R3,R4): 页面修改、保存、刷新和后端重载一致；路由、规则、日志开关实际生效；其他池配置不变。
- A4(R2,R5): 目录成功、失败、过期、缺字段、来源变更/晚返回均不冒充余额或授权；额度调研有接口/文档证据。
- A5(R7): gofmt、go test、go test -race、go vet、go build、node --check、本地浏览器验收记录；不足项如实列出。
- A6: Trellis 和业务变更提交 Git；临时产物登记 `_tmp_artifacts.md`，未经同意不清理，不部署、不推送。
