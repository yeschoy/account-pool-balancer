# TokenHarbor 注册归档、退回与套餐模型调研

## 目标
用户要求：注册机增加“已入池”分类，默认不显示已入池记录；号池账号操作增加退回注册机；核实能否按套餐返回模型列表。按项目复杂跨层任务约定留存最小 Trellis 记录，直接执行，不启用子代理。

## 已确认事实
- `internal/server/web/tokenharbor.js` 的注册记录目前全部显示，批量选择基于当前任务的 rows。
- `internal/thsignupstore/store.go` 已有 imported 状态、accountId、加密会话/Key/接码资料；不需新建存储格式。
- `internal/server/tokenharbor_registration.go:thImport` 加号池前重新检测套餐，号池使用原 config.Accounts。
- `internal/server/web/app.js:accountRow` 把 TokenHarbor 目录数量显示成“可用模型”，但后台仅获取 `/v1/models`，并未确认套餐覆盖。

## 需求与验收
1. 当前任务有“待处理 / 已入池”页签及数量；初始显示待处理。入池后下一次刷新进入已入池页，选择只作用于可见记录，切换分类清空选择；批量/单行操作期间不可切换。
2. TokenHarbor 号池操作菜单及已入池记录提供“退回注册机”。显式确认后移除号池配置，原注册记录恢复 registered/unverified，清除账号关联，保留 Key、会话、接码资料、套餐观察及固定出口。不注册、不付款、不请求上游。
3. 只按原账号 ID 与原 Key 关联，不能按邮箱猜测；无原记录、关联歧义、Key/来源变化或忙状态均拒绝。中途持久化失败不得自动重新入池或抹掉凭证，提供人工可重试路径。
4. 退回和入池的本地提交阶段互斥，网络检测不持锁；晚到的入池检测不能重新加入刚退回的账号。
5. 调研官方模型目录与套餐数据来源，区分目录、套餐覆盖、钱包付费可调用；本轮先改正目录文案，不猜测覆盖、不改推理路由、不调用付费推理。

## 非目标
本轮不部署，不改变套餐/支付/调度策略，不恢复不存在的注册会话，不自动按公开 tier 字段裁剪下游 `/v1/models`。
