# 设计与安全边界

- 会话：先读取两跳实际形态与Codex/Claude契约。复用identity/HMAC，不以UA、Key或request-id伪造会话；客户端缺身份保留message_hmac。修复确定的兼容入口及窄别名，所有新标识同步脱敏。
- 套餐：复用Poller与Snapshot；selected budget仍按Key类型，订阅名称/PAYG独立读取和展示，预算成功不能被可选订阅403抹成失败。新字段可选、旧数据可读，来源变化与晚返回保护沿用现有机制。
- 容量：沿用Pool全局4096 LRU硬上限，检查持久化Responses被淘汰时dirty标记及fail-closed边界；优先展示现有上限，不重建缓存系统。
- 错误：先分终态请求与尝试事件，明确服务端确定性错误是否确有换号收益；仅基于证据改默认规则/迁移，管理员自定义规则不得被整体覆盖。
- TPS：按单次实际上游调用计时；使用上游真实输出usage，不按字符猜token。流式输出阶段与非流式全调用平均值标注不同basis；不把排队/之前尝试计入。逐帧转发、不缓存完整输出，未知值保留空。
- 性能：先小型基准；优先减少原生SSE字符串帧的JSON映射分配及无图片数组的无意义解析。对转义键/空白/未知块保守回退，不降低无损及错误处理契约。
- 运维：入口配置若必须修改，只限已确认vhost并先备份/nginx -t；应用按既有OVH干净快照/Compose仅image流程，保留双别名/healthcheck及一致备份。无关临时产物登记_tmp_artifacts.md，经同意清理。
