## 证据

| ≥200k 输入 | 样本 | 绑定 `hit` / `miss` | 首事件 P50 / P95 |

| 零缓存 | 70 | 8 / 62 | 10.976 / 46.103 s |

| ≥90% 缓存读取 | 994 | 994 / 0 | 2.770 / 5.114 s |

- **冷路由是首要线索。** 零缓存的 70 条均为单次尝试，0 次请求内换号/容量溢出；62 条由 `smart` 新选，8 条沿已确认绑定。`message_hmac` 的 63 条绑定 miss 中 61 条零缓存（96.8%），965 条绑定 hit 中仅 6 条零缓存（0.62%）；余 3 条零缓存是显式会话头（2 hit / 1 miss），没有 body 会话。67 条 `message_hmac` 零缓存的已记录候选头为空，实际使用 `session_hmac` 填充 cache hint；显示 `message_hmac` 并不等同于必然低命中，951 条同来源请求也达到了 ≥90% 读取。1 个下游 Key 汇集全部长流量，不等于一个真实客户端/会话；零缓存覆盖 50 个匿名上游账号，不支持先封禁某单一账号。
- **不只是「零缓存组更长」。** 200k–250k 桶（24 零、331 高）P50/P95 `4.717/24.792` vs `2.350/4.075s`；250k–400k 桶（17 零、459 高）P50 `10.588` vs `2.694s`。另按同一账号/下游 Key 和同一进程时段、输入长度 ±20%、开始时间相差 ≤20 分钟取最近高缓存对照，匹配 30 条 / 29 个不同对照；29/30 条零缓存更慢，配对差中位 **+6.738s**。这是控制部分混杂的自然样本，未控制真实会话、生成参数、内容和供应商节点，不能推成因果实验。
- **本机重启不是零缓存集中触发点。** 重启前 63/802，重启后前 10 分钟 2/91，之后 5/181；前后流量构成会变化，不主张重启能改善缓存。新版有细分 timing 的 7 条零命中从请求写完到响应头 P50 **6.697s**，264 条高命中同段 **2.603s**。初步延迟差主要出现在出站发送完成后的等待，不可将其全算成模型预填充。新版窗口内零命中 7 条里 3 条沿复用连接、4 条新建；高缓存 264 条里 258 条复用、6 条新建，样本小且受冷路由影响，不能认定新建连接导致零缓存。所有 1,074 条长样本都走固定代理，无直连对照。
- **粘性不是缓存的充分条件。** 两条可关联的显式会话零缓存，找到同一标识、同一账号和 cache-hint 来源的近期高缓存前序，长度差小于 20%，且前序已结束；两次间隔约 12/23 分钟，仍在当前显式 30 分钟 TTL 内。实际前缀、上游最终 affinity 是否完全相同、服务商缓存寿命/节点未知；不能证明是上游驱逐。`layout.fallback` 在 55/70 零缓存与 485/994 高缓存都出现，运行快照布局 checkpoint 8,192 条达到上限；fallback 是值得看的一条线索，不是缓存失效证据，更不能直接扩容或禁用布局还原。
- **TTL 与容量证据不同。** 线上配置：粘性开启，弱身份 TTL 600 秒、显式 1,800 秒，保留共享 4,096 条。远端单次 checkpoint 为 26 条有效 Mistral 持久绑定（1 条显式），不是进程内全部绑定，更不是窗口峰值；没有证据证明 4,096 上限触发。`miss` 把首次、新弱指纹、过期和已被淘汰/删除混在一起。原始日志没有弱身份 HMAC 或首消息指纹，不能据此选择「把 TTL 调大」或声称「肯定是首消息改写」。

## 建议执行顺序与验收

1. **优先选择一个可控的真实客户端/隔离渠道做稳定会话验证**。使用已有 `X-Session-Id` 或该客户端已支持的稳定会话字段；确认经过 NewAPI 到 Balancer 请求摘要真的显示有效 header 和 `sessionSource=header`。同一逻辑会话保持值，不同会话不同值；切勿把整个下游 Key、用户名、固定常量或每请求 ID 当作会话。上线不擅改全量渠道、历史或用户原有 cache key。新标识通常有首次冷请求，比较第二轮及后续自然样本，按相同模型/路径、输入长度和间隔分桶。记录绑定 miss、零缓存比例、首事件与首输出 P50/P95、失败/取消，不承诺某个绝对收益。
2. **同会话同号仍掉零时，再做有限且明确授权的现有 `cacheAudit`**。仅一个选定 Mistral 下游 Key，30 分钟或 128 条先到，默认关闭；现实现需正常启动时指定选项，另走运营授权/发布约定。看 `previousClient` → `previousPrepared` → `attempts[].previous` 的共同历史前缀、cache-key/affinity HMAC、工具顺序与账号源；只把未重叠同范围做可比证据，不保存正文，不把同连接当模型节点。若自然样本不足则明确未证实，不为填样本擅发生产推理。若确认弱身份相同、常见间隔刚超过 600 秒后才掉出绑定，再考虑范围明确的 TTL 调整；若发现是同会话前缀变化，优先修透传/稳定性，不靠扩大 LRU 或静默剪历史。

本轮无业务代码/线上设置变更，没有新建 Trellis 任务，不改变既有 3 亿 TPM 待验收状态。待实际验证前不描述为「缓存已修复」。
