# 自测-test Mistral前缀与缓存审计

## 用户请求

只查看自测-test这把Key的请求和详情，按同一业务会话排查账号池是否造成低缓存，包括重排序等全部本地链路；有本地缺陷则解决，不能仅归因上游。

## 约束

- 严格按精确Key ID筛选，不分析其他Key的请求正文/详情。
- 真实正文、图片、身份、凭据只在远端内存；本地只保存脚本、脱敏指纹与结构计数。
- 不改变生产配置/详情开关，不部署/重启、不主动推理/重放/扫号；不承诺best-effort缓存保证。
- 不删除、重排或压缩用户消息/工具/思考来制造命中；不覆盖其他窗口注册相关改动。

## 验收

1. 对齐该Key所有可用详情及截断边界，不将截断日志当完整payload。
2. 对客户端→实际上游逐项核对字段/消息/工具数组顺序、内容、参数、缓存键、头、账号/attempt及原生usage。
3. 同Key内区分可验证的技术子会话，不混用不同账号/工具集作为同前缀证明；用户业务上同会话不等于每次模型调用同完整prompt。
4. 用本地合成数据和真实HTTP上游捕获覆盖完整body/属性顺序/大历史/适配前后连续性；有真实缺陷则先复现再最小修复。
5. 分清已排除、本地已修、上游待确认和未验证；不得无证据宣称缓存已改善。
