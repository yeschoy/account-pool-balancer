## 采样口径

- OVH 上原地只读解析最近 18 个 Balancer 请求日志分段，按日志中请求开始时间过滤 UTC `2026-11-22 19:18:54.523` 至 `2026-11-23 19:18:54.523`，共 14,582 条 Mistral 请求记录。伴随错误日志单独计尝试，不和最终请求数相加。只返回汇总，未输出请求标识、客户内容、会话/凭据或代理地址。跨窗口未写完或日志已丢弃的请求不在样本内。P95/P99 为最近秩分位数。
- 请求日志 `ttftMs` 是网关准备发送首个可转发数据事件前的时间，可是角色、思考或生命周期帧，并非客户端首个正文；`streamMaxLagUs` 是一条流内从上游完整事件读出到下游写入**前**的最大延迟，不含 Write/Flush 阻塞、NewAPI 或公网。`durationMs - 最后 attempt.ms` 仅近似入站读取/准备/准入及尝试外收尾，含可能的前序尝试（本窗口有重试的最终均失败）；不能直接当路由排队或适配 CPU。
- NewAPI 对应 Nginx `/v1/` 配置文本已设 `proxy_buffering off`、`proxy_request_buffering off`，保留旧下划线会话头；未修改或 reload，未测 NewAPI 自身逐帧开销、实际客户端链路首正文或跨层对应分位。不要重复推荐笼统关闭入口缓冲。

- **结果可信度**：当前 Mistral Chat 已逐 SSE 事件适配/Flush，不等整包。Responses 明确检查终态，Chat 沿用传统 EOF 兼容，未观察到 `[DONE]` 也可能记成功；现有成功数是日志语义，不能反推出输出完整率。DeepSeek Chat 有 242 个成功流的 `durationMs-ttftMs` 小于 50ms；现 `upstreamTps` 把总 usage 除以首末事件间距，极短或批量推送的窗口可产生夸大的值，不能当模型解码速度。

## 推荐实施与验收顺序

1. **分段低成本观测**：在不改变现有 `ttftMs` 口径下，区分上传/请求准备/入池等待、每次 attempt 的连接等待/复用、写完上游请求、响应头、第一事件、首思考/工具/正文成功 Flush、末有效事件/终态/尾窗。超低延迟字段允许缺失；记录连上游但未拿头的失败，不把空字段当 0。SSE 阶段的下游写阻塞单列。NewAPI/入口用相同合成固定负载对照，关联已有请求标记而非记录原始请求/会话/凭据；不发付费生产测试，授权前先用本地 mock。旧、新指标可并存，不伪造首字、不提前写 200 影响错误处理；TPS 区分客户端观察吞吐和供应商解码，极短窗口不报速度。
2. **减少真实业务尾延迟/失败**：按模型/协议、输入长度和缓存比例分桶，查 ≥200k 且未命中请求的绑定结果、身份来源及历史稳定性；先试稳定显式会话和客户端主动压缩，保持已发送正文、键、隔离、套餐与付费语义。针对 500 先证实跨账号同类错误与准确规则，才考虑总重试预算或某个模型/错误码的短退避；保留确定可恢复的故障切换及无重放边界。单独评估长时间无上游响应的非流超时及 NewAPI 外层超时，保留正常长请求。明确协议错配、400/422确定性失败以及流截断。调整 Chat EOF 前，先验证供应商允许的终止序列、有无 usage-only 末帧/不发 DONE 等变体，再灰度修正结果；已输出不重放、不补 DONE。
3. **仅优化已测热路径**：同轮基准比较 128 KiB、512 KiB、2 MiB 及包含真实形状思考/工具的合成 Chat；一次索引复用路由/适配字段，处理布局时借用旧历史 offsets，减少第二次渲染和同一帧重复解析。保留 JSON 错误和重复字段、顺序/闭合/数字、命中/失败回退、缓存/会话原值规则与用量计费；不等待多帧来降低 Flush 次数。按路由和协议给出 B/op、峰值保留内存/GC、网关 P95/P99 和长流并发回归。仅在实测连接排队时再考虑上限、冷连接或出站网络，不能用自然峰值或本地 Mock 冒称 3 亿 TPM。
