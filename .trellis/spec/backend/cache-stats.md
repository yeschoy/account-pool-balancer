# Rolling cache-hit rates and administrator reset

- `internal/stats` is the source of rolling minute-bucket counters, never reconstruct counters from request logs. `p/k/i/o` are original24h usage; `cp/ck/ckr` are paired measured prompt/cache samples and their count. UI hit rate is `min(ck/cp,1)` only with `ckr>0 && cp>0`; missing/legacy-only measurements are unknown (`—`), not a zero-percent miss. This is a token-weighted read share, not the percentage of requests with cache hits.
- Account rows, overview and per-model rates use the same measured counters. Show measured denominator and sample count; an explicitly measured zero cache read is0%, but no samples or zero prompt denominator is unknown. Cache write tokens never count as reads.
- `POST /api/stats/reset-cache-rate?provider=<pool>` requires the existing administrator session, same-origin and CSRF middleware. Require one recognized non-Perch scheduler pool; missing/unknown/Perch cannot become an all-pool reset. Perch has its own statistics/UI and is deliberately not included.
- `Stats.ResetCacheRates` holds the existing stats mutex and clears only `cp/ck/ckr` across the selected provider's global/account/model/proxy rings. Subtract only matching-minute contributions from overall rings; preserve every other provider. Repeated/no-traffic resets are safe. Requests completing after the reset count immediately, including in the same minute.
- Preserve original request/success/failure/cancel counts, token usage including cached reads/writes, costs, timing, health, routing, bindings and logs. Do not delete buckets, clear upstream caches or alter configuration. Clearing a rate does not change individual historical request-log rates.
- Persist through the existing forced metadata save before acknowledging success. A disk failure returns500 explicitly stating the in-memory reset occurred but persistence failed. Normal export/import must not reconstruct cleared measurements from raw usage. Reset remains effective across restart and still expires with the original rolling24h window.
- Console has an overview reset button with explicit pool confirmation, non-reentrancy and error feedback. Capture the pool before confirmation; switching tabs cannot target another pool. Refresh overview/account data on success. No production resets as part of validation; use disposable local credentials/data only.
- Storage is sparse by observed minute with a cached rolling total; a single-provider account may share its overall/provider ring, but the same ID in multiple providers must split. Import may relink equal projections. Mutating resets/expiry/Import must update cached totals and preserve exact legacy export schema; never infer known tokens from absent data. Empty expired account/model/proxy entries are reclaimed, including room for new bounded model/proxy keys. See `mistral-capacity.md` and `stats/capacity_test.go`.
- Required checks: `reset_cache_rate_test.go` (all projections, other-pool isolation, same-minute new traffic, JSON persistence,24h expiry), `cache_rate_test.go` (authentication/CSRF, explicit provider, metadata and config preservation), `cache_rate_web_test.js` (known/unknown/zero, account row, cancel, captured provider, refresh and errors). Real local browser must confirm the account column and reset postconditions.
