# 新号池完整交付契约

用户在2026-11-08明确要求：所有新增号池至少具备TokenHarbor同等完整管理能力；不能等用户逐项发现缺失。任何新池任务与验收必须逐项覆盖下面矩阵。

| 能力 | 必须证明 |
|---|---|
| 账号管理 | CRUD、启停、批量导入/重复处理、Key/代理、安全管理员查看/复制；并发/RPM/权重/优先级确实参与现有调度 |
| 隔离 | provider/group/client/import Key和模型目录隔离；不使用另一个池的Key、额度、配置或规则 |
| 额度 | 调研普通Key/会话的真实接口；手动刷新→请求→强类型校验→Snapshot/metadata→account API→页面全链路；重启后保留；失败/权限/缺字段/过期不是零；共享预算不可重复累计 |
| 路由 | 可见且可持久化的独立选号策略、粘性/会话头/TTL、忙时处理、并发/RPM与等待、单请求尝试上限、健康阈值、超时、体积/缓存、轮询参数。不同池共用的参数必须明确标出，不能保存本池时意外影响别池 |
| 错误规则 | 独立默认值、列表/增删改/启停/排序、状态/正文/响应头匹配、作用域/动作/冷却/恢复时间/额度刷新/下游状态；保存与重载后实际参与处理 |
| 重试规则 | 独立默认值、可视编辑、持久化、终止/重试的真实决策；流已输出、状态续传、未知结果等安全门不可被配置绕过 |
| 日志/诊断 | 请求、错误、详情入口与开关/保留策略；来源/分类/请求链路可诊断；凭据和会话标识不泄漏 |
| 连通测试 | 厂商正确的默认模型、明确只读/真实推理差异，保留手填模型；目录可见不等于推理授权 |
| 验证 | Mock数据/失败路径/权限/晚返回/来源变化/跨池隔离；真实本地浏览器操作保存与刷新并核对后端状态，不能只靠HTTP200或按钮点击成功 |
| 部署 | 需明确授权；保留配置和业务数据、备份回退、容器健康/版本、公网及NewAPI渠道实际路径验证；不把Mock当成生产实测 |

## 不适用项
不支持的协议、钱包、额度或上游能力要逐项说明，并在UI中解释不适用原因，不放无效开关。未知币种/额度不得猜测。不得为追求能力对齐而自动开启PAYG/钱包消费、修改代理/账号策略或丢弃调用者字段。

## Done门禁
交付状态必须分开写：接口证据、后端刷新、页面展示、保存重载、测试、提交、推送、部署、线上验收。仅修改测试默认模型或写接口核查文档不等于额度功能已接入。若有缺项，明确剩余工作，不能宣称“号池已完整完成”。
