# Mistral cache, reasoning and Chat content adaptation

## 1. Scope / Trigger
Mistral Chat/Responses generation request preparation and the narrow Mistral Chat response content-list compatibility boundary. Use the original scheduler, account admission and replay safeguards. Responses/FIM/other providers remain native; this is not a general protocol converter.

## 2. Signatures
- `prepareMistralRequest(body []byte, path, fingerprint string) ([]byte, string, error)` returns prepared body and generated private cache key.
- `mistralChatMessages(raw []byte, developer bool) ([]byte, bool, error)` normalizes complete Chat history, not only the leading routing messages; developer conversion is exact-model only. Parameter failures use local400 `invalid_mistral_request`, category request, before admission.
- Invoke request preparation after strict JSON/model/stateless-response validation and identity selection, but before account/RPM acquisition.
- `mistralChatResponse(body []byte, stream bool) ([]byte, error)` maps Chat `message`/`delta` content lists to OpenAI string content and reasoning_content.
- `mistralChatEvent(event []byte) ([]byte, error)` adapts exactly one complete SSE event before its immediate downstream flush.

## 3. Contracts
- Exact generation paths: `/v1/chat/completions` and `/v1/responses`. Add `prompt_cache_key=apb-mistral-<existing session HMAC>` only when absent and identity exists. Existing values, including explicit null/empty, are never overwritten. Scope is already group plus downstream-key ID. No random request IDs/raw identities/credentials in generated values or logs; add generated values to private-identity redaction.
- Only Chat assistant top-level `reasoning_content` is adapted. Nonempty string becomes a leading `{type:"thinking",thinking:[{type:"text",text:...}]}` chunk; preserve original string answer or append original content chunks, keep tools/tool IDs/unknown fields. Null/empty reasoning is removed without inventing content. Unsupported reasoning/content types fail locally without acquiring accounts. Responses reasoning is untouched.
- Only exact DeepSeek Chat additionally treats assistant top-level reasoning string/null as an alias for reasoning_content (production422 extra_forbidden at body.messages.4.assistant.reasoning,14 recovered previews, all string inputs). Preserve nonempty thought via the same leading native thinking chunk; keep original answer/tools/order/numbers. Identical aliases produce one thought, empty/null alias may defer to a nonempty canonical value, but conflicting nonempty values, invalid types or duplicate alias fields fail locally before admission. No stringification or dropping unknown reasoning objects/arrays; other models/protocols retain original alias bytes.
- Only exact Mistral DeepSeek Chat accepts root reasoning={effort:<value>} as an alias for reasoning_effort. The object must contain exactly one effort field; malformed/extra fields (including summary/budgets) and duplicate root/nested fields fail locally before admission without echoing values. Both spellings share the operator's low/high normalization; omitted/null/unsupported values and invalid effort types map to high. Semantically equal normalized values collapse to one native field; conflicting normalized tiers fail rather than choosing one. Resolve aliases before applying the missing-controls high default and write the native field only once. Assistant-history reasoning aliases remain separate; Responses/FIM/other models/providers retain their native root reasoning bytes.
- Operator policy (2026-11-08, latest request): only Mistral Chat model `deepseek-v4-1-flash-1017` forwards low/high. Missing/null/empty/unsupported effort (including max/none/medium/xhigh/minimal) and invalid effort value types map to high. This supersedes the earlier wider upstream-tier/default/null/disabled-switch behavior. Preserve supported explicit tiers and escaped wire bytes. Do not apply this model-specific policy to Responses/FIM or other models/providers, raise output budgets, or promise cache improvements; high may increase reasoning usage/latency.
- Top-level/message wire splicing leaves unrelated original fields (including root model/tools/numeric values) untouched; unchanged requests retain original bytes. RawMessage keeps message numbers/tool arguments lossless when reasoning content is adapted. Only the exact-model Chat exceptions below may consume unsupported parameters; unknown fields remain native. Do not promise all historical 422 errors share one cause.
- Only exact DeepSeek Chat maps developer→system, replacing the role value without moving messages or changing any other message fields. Adapted messages must not silently collapse duplicate fields; duplicate role/content/reasoning_content is locally rejected when adaptation would be ambiguous.
- Only exact DeepSeek Chat first removes empty/null NewAPI internal image_url.MimeType metadata (live validation confirms extra_forbidden; the synthetic control without it passes image schema validation). Reject duplicate MimeType before admission, including escaped keys; retain nonempty values and real image options. Then unwrap user content image_url={url:<string>} into native image_url:<string>, including base64 data URLs, across the full history. Preserve image bytes/URLs, text and chunk order, tools, numeric precision and unrelated root fields; never remove an image or switch models. Native string URLs and objects with additional options (e.g. detail) remain native rather than silently discarding requested semantics. Duplicate consumed fields and a URL-only object's non-string url fail locally. Other roles/models/protocols/providers are untouched. Production422 at body.messages.28.user.content.str plus recovered image_url object/data-URL shape motivated this narrow adapter; the official model page explicitly supports text and image inputs, so do not misdiagnose it as text-only. The first union-branch error does not prove all content arrays are invalid, nor does mock success prove the production request was fixed.
- Only exact DeepSeek Chat consumes thinking={type:enabled|disabled} (no other keys/budgets) and boolean enable_thinking. Duplicate/unknown/malformed switches and unknown budgets still fail locally. Well-formed switches are compatibility-only and cannot override supported explicit tiers or generate none; omitted/unsupported effort always defaults to high even with disabled/disagreeing switches. Root reasoning objects still require exactly one effort field, and conflicts between normalized explicit effort spellings remain local400.
- Only exact DeepSeek Chat maps integer seed→random_seed losslessly. Explicit random_seed is never overwritten; nonidentical integer values or a nonnull seed against explicit null conflict locally. Null seed is an unspecified default and may be omitted. Generic official schema documents random_seed but production support/determinism for this specific model is still unverified: no dropping it on failure, no inference replay or account sweep to manufacture success.
- Only exact DeepSeek Chat omits logit_bias=null/empty object and verbosity=null/medium (unspecified/default); other values are locally rejected rather than changing requested generation. user/safety_identifier string/null are compatibility-only client labels, omitted without claiming upstream tracking/safety semantics. Generic user labels are not conversation identity; the shared routing parser may recover only a recognized Claude compound/JSON session structure from user before this field is removed. prompt_cache_retention=null/empty string may be omitted; any explicit retention request is rejected because it cannot be guaranteed.
- Client prompt_cache_key/metadata wire values and existing identity selection remain intact, including null/empty. Mistral alone accepts X-Prompt-Cache-Key/Prompt-Cache-Key as a final explicit header fallback after the preexisting body/session identifiers and before message_hmac. Only session-bearing Claude structures (legacy _session_UUID or JSON-string session_id) may be recovered from metadata.user_id or root user; generic user/UA/request-id never identifies a conversation. No global constant cache key or scheduler/TTL changes. Duplicate adapted root fields, messages, metadata or cache key are rejected in the exact-model scope before admission, including escaped duplicate keys.
- Exact-model stateless exception: Mistral Chat `deepseek-v4-1-flash-1017` rejects even `store:false/null` (production422 loc body.store). Remove that single root field only; preserve its neighboring fields, original content/tools/cache key and nested metadata.store. Reject true/non-bool/non-null/duplicate store locally before any account acquisition; never pretend server-side persistence was requested successfully. Responses/FIM/other models retain their contracts. Omitting this unsupported flag is not a guarantee about provider-level data retention.
- Responses is stateless: full input history, no previous_response_id and store omitted/false/null. Other pools/endpoints do not use request preparation.
- Mistral upstream HTTP errors retain the existing64KiB response prefix; read at most one additional byte solely to identify truncation. Emit responseBodyTruncated when actually over the cap. Structured mistralValidation diagnostics may recover allowlisted loc/type from complete or truncated JSON/detail lists and JSON-string message envelopes, bounded in depth/count. Never traverse or log input/ctx/message text, request bodies, user-defined paths, identities or credentials. This is diagnostic only: do not change forwarded error bytes/status, replay/account-health policy, or raise the body cap to retain echoed prompts. Unknown422 remains unknown until evidence arrives.
- Chat response arrays containing `text` and unsigned `thinking` (nested text chunks) map to string `content` and `reasoning_content`; retain tools, IDs, finish reasons, usage, unknown message/root fields and exact JSON numbers with RawMessage. Existing string/null content keeps original bytes. Empty thinking/closed transition markers produce no invented text. Merge an existing string reasoning_content without discarding it.
- Only Mistral `/v1/chat/completions` responses are adapted, both JSON and SSE. Each event is emitted/flushed immediately; never buffer the whole generation. Preserve SSE id/event/retry/comments, delimiters and `[DONE]`; do not fabricate completion. Responses, FIM and other providers keep native bytes.
- Unknown chunk types/metadata, reference chunks, malformed text or nonempty signatures fail explicitly instead of silently losing content. Before commit:502 `mistral_content_unsupported`, category compatibility, no replay/account health penalty. After commit:one error SSE, failed request outcome, no fake `[DONE]`, no replay/account health penalty. This does not disable reasoning or fix unsupported content by dropping it.
- Administrator account Key/control Key/proxy display/copy is explicitly authorized by the user, across pools. It uses already-plaintext config values, admin-session/no-store APIs and escaped vanilla UI. Do not change import isolation or log redaction, add encryption, migrate password/Cookie stores or expose credentials through runtime-key auth.

## 4. Validation & Error Matrix
| Input | Outcome |
|---|---|
| Missing cache key + known session | Stable HMAC key, caller-isolated |
| Supplied cache key / no identity | Preserve supplied value / do not generate |
| Assistant reasoning string + text/chunks/null content | Preserve reasoning and original answer/tools in native chunks |
| Null/empty reasoning | Remove only empty incompatible field |
| Exact DeepSeek Chat assistant reasoning alias string/null | Preserve thought through native chunks; conflicting/invalid/duplicate alias locally rejected |
| Exact DeepSeek model / Chat / generic medium effort | Supported high; all other tiers/models/protocols unchanged |
| Exact DeepSeek Chat developer messages | Replace role only, keep original order and content/tools/numbers |
| Exact DeepSeek Chat root reasoning={effort:...} | Convert to one reasoning_effort; same normalized aliases accepted; conflicts/unknown fields/duplicates locally rejected |
| Exact DeepSeek Chat missing both effort spellings and both thinking switches | Inject high; retain tools/history/cache/metadata/numbers/output budget |
| Exact DeepSeek Chat native/nested null, unsupported tier or invalid effort value type | high |
| Exact DeepSeek Chat supported low/high + well-formed switches | Preserve supported tier; switches never emit none |
| Exact DeepSeek Chat missing effort + enabled/disabled/disagreeing switches | high |
| Thinking budget/unknown structure or conflicting normalized effort aliases | Local400, zero upstream attempts |
| Exact DeepSeek Chat user image_url={url:<string>} | Native string URL/data URL, preserving images/history/text; extra options stay native |
| Exact DeepSeek Chat seed + absent/equal random_seed | Lossless rename / preserve explicit random_seed |
| Conflicting/invalid seed; meaningful unsupported generation/retention | Local400, no silent loss or retry |
| Exact DeepSeek Chat root store=false/null | Omit unsupported root field only |
| Exact DeepSeek Chat store=true/invalid/duplicate | Local400, no upstream request or fake persistence |
| Assistant-history object/number/array reasoning or unrepresentable content | Local400, zero upstream attempts |
| FIM/embedding/token-counting/other pool | No transformation |
| Chat text/thinking response arrays | Per-frame string content/reasoning_content; tools/usage preserved |
| Chat native strings, usage frame, DONE/error/comments | Original event bytes |
| Unrepresentable response chunk before/after SSE commit | Explicit502/error SSE; no replay or account penalty |
| Anonymous/runtime-key admin read |401, no Key/proxy disclosure |

## 5. Good / Base / Bad Cases
Good: old DeepSeek-style assistant history is normalized before a Mistral request and receives a stable missing cache hint; returned thinking/text arrays become string fields NewAPI can parse. Base: already-native string responses and history with a client cache key retain their bytes. Bad: remove reasoning/tools to hide a422, reuse one global cache ID, treat NewAPI `<think>` formatting as outbound request adaptation, or hide parser errors by marking an unsupported response complete.

## 7. Wrong vs Correct
Wrong: overwrite a caller's prompt_cache_key, forward raw session IDs, change other providers' payloads, or conclude `stream_status.status=error` with `end_reason=done` proves a transport interruption. Correct: inspect structured parser errors, adapt only documented Mistral Chat content chunks and missing cache hints, preserving state/routing/accounting and actual per-frame streaming.

## 8. Session, subscription and hot-path additions (2026-11-08)
- Codex official session-id/thread-id and legacy underscore aliases are recognized, with bounded compatible Claude/Codex header variants and parent IDs. Nginx must allow legacy underscores in the NewAPI vhost; application aliases cannot recover headers already removed upstream. Absence at both NewAPI/Balancer legitimately retains message_hmac. New identities remain downstream-key isolated and private in detail logs.
- Existing global4096 LRU remains shared, not4096 per account/pool. Overview exposes bindingLimit/globalBindings separately from current-pool bindings. Capacity eviction uses the common delete path so a persisted strict continuation removal marks metadata dirty; a missing strict owner fails closed, never silently switches accounts.
- Billing still selects API/Vibe budget by whoami key type. Optional /billing/subscription (3s bounded, no redirects) adds independently cloned/persisted plan/PAYG flags, read/check times and errors. Whoami key-access plan and organization subscription are distinct; API Free + organization Student is valid. Optional failure preserves fresh budgets and last-good subscription with historical/error marking; nullable flags remain unknown and are read-only.
- Default 503 + exact top-level code3800 is model/service failure: action ignore, no key health penalty or account rotation, preserve Retry-After. Other5xx and useful429 recovery retain existing policies. Upgrade only exact prior factory error/retry lists; preserve any administrator customization/order/notes/explicit empty list.
- Native single-data-line string SSE frames bypass JSON map decoding and allocation. Multiline SSE, content lists, unicode-escaped keys and uncertain cases conservatively use the original full adapter; pure-text request arrays skip only image-object decoding after duplicate-content validation. No dropped fields, thought, images, tools, usage or weakened validation. Benchmark claims describe local fixtures, not upstream model generation or end-to-end latency.
