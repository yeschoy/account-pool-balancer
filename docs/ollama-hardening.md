# Ollama 账号池：并发与隐私加固

本轮为既有 Ollama 池的小范围后端加固，基线 `e210871`。不新增调度器，不改已保存配置、不自动提高账号并发/RPM，也不引入浏览器/TLS 伪装或出口轮换。

## 已实现

### 连接池与刷新

- 共享 HTTP Transport 缓存改为 `sync.Map`：命中不再经过全局独占锁；首次创建和设置变更仍受互斥锁保护，同一路由复用一个 Transport。
- 保留 HTTP/2、keep-alive、已有直连/代理连接上限和设置变更时关闭空闲连接的行为。Mistral 的独立连接配置与清理同步适配新缓存容器，不改变其参数语义。
- Ollama 推理不再登记 OpenDesign 的模型级计费预检；其他池的新模型也不再因此重排 Ollama 刷新。
- 同账号并发手动刷新共享进行中的结果；成功和失败均适用至少 30 秒刷新间隔，连续点击不会排队重复打 `/api/balance`。间隔内返回上次结果及原时间戳，不伪装为本次新读取。等待者取消不会取消已有读取。
- 元数据目录深拷贝移出 quota 锁；缓存命中的刷新不再拷贝大目录。实际网络请求仍在池锁之外。

### 额度来源隔离

- 用现有 `CatalogSource` 哈希将 Ollama 元数据绑定到 provider、运行 Key、代理和上游地址，不保存原始凭据到来源字段。
- 更换来源立即丢弃旧额度、鉴权判断和派生绑定；上游地址变更也清理模型缓存。
- 旧来源的慢请求不能重新写回；重启只加载来源匹配的额度。旧版本无来源标记的 Ollama 元数据会失效并等待重新读取，不把未知当零。
- 同来源读取失败保留最后成功的金额和时间戳，标记错误并退避；不把失败写成余额 0。

### 出站隐私边界

所有 Ollama 推理、余额、模型目录和管理员诊断请求均使用同一出站客户端边界：

- HTTP 请求头默认拒绝未知字段，仅保留 `Authorization`、`Content-Type`、`Accept`、`Anthropic-Version`、`Anthropic-Beta`。
- 使用诚实的 `account-pool-balancer/ollama-gateway` UA，不透传真实客户端的 OS/浏览器版本、设备/安装 ID、SDK 信息、语言、会话头、Cookie、Origin/Referer、追踪头或客户端 IP 头。
- 不再为 Ollama 生成浏览器 Client Hints。
- 不跟随任何 301/302/303/307/308 重定向，包括同主机重定向；固定代理失败不回退直连。
- 不修改调用方 request/header/client，不替换原 Transport，不破坏连接复用。请求正文、查询参数、工具调用和原生 SSE 不因隐私过滤而改写。

这是防止**请求头意外泄露客户端设备信息**，不是匿名化保证：显式写入正文/查询参数的 `user`、`metadata`、设备字段或业务文本仍会发送；上游仍能看到 API Key、服务端出口 IP 和网关 TLS/HTTP 特征。没有实施跨账号防关联、浏览器伪装或绕过风控。

## 本地验证与性能边界

新增本地 HTTP mock 回归覆盖：三协议原有兼容、真实推理边界隐私过滤、原正文/查询参数不变、原生 SSE、32 路额度刷新（成功/401/429/503）、等待取消、旧来源晚写、持久化重启、来源变更、代理失败和并发缓存失效。

并发回归使用 4 个账号、每账号并发上限 4、64 个并发请求：全部成功，未突破账号上限。该测试证明本地 admission/连接路径的正确性，不证明线上 Ollama 容量。

Apple M4、Go 1.26.8 的 `BenchmarkOllamaTransportCache`（3 次，8 路并行）：

| 缓存查找 | ns/op 范围 | allocs/op |
| --- | ---: | ---: |
| 原独占锁路径 | 122.5–146.3 | 0 |
| 新并发缓存路径 | 4.373–4.529 | 0 |

单路下新缓存约 19 ns/op、原约 10–11 ns/op：为并发可扩展性接受个位数纳秒额外开销。此处仅测缓存查找，不能外推为整体 RPS/TPM 改善倍数。初试 RWMutex 未显示明确收益，未采用。

本轮不添加新的 Ollama 独立设置块：它仍继承现有共享 Routing/Quota 设置，账号上限沿用 `maxConcurrent`/`maxRpm`。生产调优需结合真实上游限流、单出口容量和流式请求持续时间；不通过盲目放大连接数承诺高吞吐。
