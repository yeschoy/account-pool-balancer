# Go 订阅号池网关：本地实现与操作说明

## 范围与交付边界

本轮按用户确认实现 **Go 付费订阅号池网关**：Codex/Claude Code 会话与缓存亲和、账号固定出口、并发/RPM、Go 概览和请求/错误日志。复用现有 config/pool/quota/stats/logstore/WebUI，没有第二套调度器、数据库或新增依赖。

- Zen、匿名/免费模型、Gemini/Google 适配不在本轮范围；其他池既有行为保留。
- 没有新增跨套餐回退、官方身份伪装、官方 prompt/tools 注入、随机出口或规避订阅限制的逻辑。
- 本地 Mock、真实浏览器 UI 测试通过不等于上游授权、真实缓存收益或官方客户端端到端认证。
- 本轮不部署、不改变生产配置、不发起付费推理。实际上线及最小真实验收需另行授权。

## 1. 会话与缓存亲和

### 会话优先级

Go 独立采用以下规则，不改变其他供应商原有 identity 顺序：

1. `previous_response_id`：必须使用已有的响应链绑定，不能随机换账号或删除字段强行重放。
2. 配置的会话头、父会话标识、请求体中的显式会话标识，以及内置 Codex/Claude Code 等会话头。
3. 无显式标识时，可按现有设置用首条 system/user 信息生成弱 HMAC 亲和。
4. `prompt_cache_key` 及支持的缓存提示头是**独立次级偏好**，不覆盖已经存在的明确会话绑定。

内置识别包括 `Session_id`、`X-Session-Id`、conversation/thread 类头、Claude Code 会话头、`metadata.user_id` 中的会话信息及父子任务标识。这里按实际信号识别；不会把每次请求变化的 `X-Request-Id` 当作会话。

### 缓存偏好不是对话状态

- 缓存 key 按下游 Key、分组、模型做 HMAC 隔离，不能把不同调用方的相同开场/缓存提示当成同一会话。
- 同会话已绑定账号优先。绑定账号忙时有界等待，超时返回本地容量限制，不静默借号溢出。
- 新会话可优先选择相同缓存提示最近成功使用的账号；该账号忙时可选别的可用账号，并记录 `busy-fallback`。这种回退不会抢走原有缓存偏好的归属。
- 缓存偏好校验凭证/代理/Base 来源；旧请求的迟到结果不能恢复旧来源的缓存偏好。
- 缓存偏好使用原有有界 LRU 和弱亲和 TTL，不落盘；它不会挤掉会话/响应链来争取缓存记录空间。
- 普通会话绑定仍是内存状态；重启后重新建立。已确认 Responses 绑定继续 checkpoint，并新增保存原上游匿名会话标识，续传和恢复不凭空换会话。

### 上游身份与原生字段

- Go 上游 `x-opencode-session` 使用调用方隔离的稳定 `apb-…` 匿名标识；有状态续传复用原来的标识。
- 保留真实客户端 User-Agent。缺失或只有已识别通用 HTTP/SDK UA 时，使用 `account-pool-balancer/go-gateway`，不自称官方 CLI。
- 原生正文不改写，保留 `prompt_cache_key`、`cache_control`、工具、metadata 等原生字段；原有其他客户端会话/缓存头继续转发，凭证与转发 IP 等敏感头仍按既有规则过滤。
- 仅凭缓存指令或同账号不能保证上游缓存命中。实际缓存统计只使用上游报告的 usage。

## 2. 固定出口及可选 IP 校验

用户确认：**账号绑定固定出口，允许多个账号共享同一固定 IP，不强制每账号独占 IP。**

已有账号级 `proxyUrl` 继续管理固定代理；留空表示宿主 Direct。推理、目录、额度和诊断都使用该账号的固定 Transport。失败时不会自动直连或轮换代理。

### IPv6 代理

网关原有 Go 标准 Transport 已支持 IPv6 代理端点，HTTP/HTTPS CONNECT、SOCKS5/SOCKS5H 均复用同一账号 Transport，不新增网络栈。本次补齐 IPv6 URL 校验、界面说明及本地真实 IPv6 socket 回归。

在账号页“出站代理”填写，IPv6 主机必须放进方括号（以下是文档保留地址，必须替换为自己的代理）：

```text
http://[2001:db8::10]:8080
https://[2001:db8::10]:8443
socks5://[2001:db8::10]:1080
socks5h://[2001:db8::10]:1080
```

认证继续使用 `协议://用户名:密码@[IPv6]:端口`，凭证中的特殊字符需 URL 编码；管理界面和普通日志不回显凭证。无方括号的歧义 IPv6 URL、无效 IPv6 字面量会在保存时被拒绝，错误消息不含原 URL/凭证。既有 IPv4/域名代理继续可用。

“预期固定出口 IP”填写裸 IPv6，如 `2001:db8::77`，不带方括号、协议或端口。完整/压缩写法会规范化，IP 探测支持纯 IPv6 文本及 `{"ip":"IPv6"}`。

**入口不等于出口**：

- IPv6 代理入口 → IPv4 OpenCode 出口，以及 IPv4 代理入口 → IPv6 出口，都可能成立；出口地址族和 DNS/连接选择由代理服务决定。
- 要固定 IPv6 出口，需要代理端实际绑定静态 IPv6 外联，并使用可信且适合 IPv6 验证的校验目标。设置预期 IPv6 后，如果探测只返回 IPv4，会按 IP 不符阻断，而非更改 pin 或绕过代理。
- 不在网关猜测/改写 OpenCode 的目标地址、不全局强制 `tcp6`，也不新增“失败自动直连/换出口”。不同目标的出口一致性仍要求代理服务正确配置。
- 服务宿主需要能访问该代理入口；若代理入口本身是 IPv6，宿主/容器也需要可用 IPv6 路由。仅安装本代码不能补出运营商或容器网络的 IPv6 能力。

**OpenCode 外网核查（2026-11-05）**：`opencode.ai` 发布四条 AAAA（`2606:4700:78::90:0:140`–`143`），说明公开了 IPv6 解析入口；[官方网络文档](https://opencode.ai/v2/docs/network/)提供标准代理配置，但没有据此给出任意 IPv6 代理/账号的可用性承诺。本机强制连接指定 AAAA 失败，不能声称真实 IPv6 Go API 已验收。普通 `curl -6` 在当前环境返回 `::ffff:172.65.90.20`，这仍是 IPv4-mapped 地址，不计为原生 IPv6 成功。在代码实现阶段尚无用户实际代理地址，未验证其线路、固定出口或带 Key 的推理权限。

**后续用户授权代理测试（2026-11-05）**：通过用户提供的 SOCKS5H 代理，IPv6-only IP 查询两次成功且观测 IP 一致；Go 公开模型目录返回 HTTP 200、29 个模型。保持原域名 Host/SNI 和 TLS 证书校验，强制连接当时公开 AAAA `2606:4700:78::90:0:143` 也返回 HTTP 200，证明该代理到 OpenCode 的原生 IPv6 路径可用。约 2.1–2.5 秒为本次模型目录请求耗时，不是推理时延。没有发送 Go Key、没有付费推理、没有改生产配置；两次 IP 一致不保证永久静态出口，公开目录不证明账号授权。代理地址、凭证和具体出口 IP 不写入 Git。

本地回归使用 `[::1]` 的真实 IPv6 TCP、TLS 和带认证代理：四种代理分别覆盖目录/能力/文档/额度/IP 检查/模拟推理、出口 IPv6 日志、IPv6 pin 拒绝 IPv4、代理断开不直连。它们是本地 Mock，不能替代外网代理验收。

### 配置字段

| 字段 | 默认/约束 | 用途 |
|---|---|---|
| `accounts[].egressIp` | 空；仅 Go，可填 IPv4/IPv6 | 可选的预期出口 IP；空值明确显示“仅绑定出口，IP 未验证” |
| `opencode.goEgressCheckUrl` | 空；管理员配置的 HTTP(S) URL，无 URL 凭证/query/fragment | 返回纯 IP 或 `{"ip":"…"}`；空值不主动联系第三方 |
| `opencode.goEgressCheckSec` | 60，范围 5–3600；0 采用默认 | 成功校验新鲜度；失败最多短缓存 5 秒，后台额度任务按既有重试节奏重读 |

设置 IP pin 前必须先配置校验 URL。相同 IP 可绑定多个账号，IPv4-mapped IPv6 会规范化。后台不会因为 URL 非空就给所有未设 pin 的账号自动探测 IP；手动“检测固定出口”可主动观测。

### 校验与失败行为

- 校验请求不带上游 Key、管理员 Cookie 或调用方凭证，走该账号相同固定代理；拒绝重定向，10 秒超时，限制响应体大小。
- 同一账号/来源的并发校验合并，不在 pool 调度锁内做网络 I/O，不消耗推理 RPM/选号计数。
- 配置 pin 后，校验失败、过期后无法重新验证或 IP 不符，会阻止该账号的推理及目录/额度查询。日志为本地 egress 拦截，不误扣账号健康分。
- 额度查询被拦截时保留旧用量/时间，标记错误和未知，不伪造 0；恢复后重新读取。
- 账号列表、Go 概览和诊断显示校验状态/观测 IP；请求与错误记录在可用时保存当时的观测 IP，避免把代理地址当作实测 IP。

**网络前提**：IP 校验只是有时效的漂移检测，不能把动态代理变成静态代理，也不能保证两次校验之间不变。真正固定公网 IP 需要宿主或代理服务提供静态出口。UI 不将未验证的固定 URL 宣称为已固定公网 IP。

## 3. 并发、RPM 与独立 Go 路由

复用账号编辑中的 `maxConcurrent`、`maxRpm`，0 仍表示不设本地上限；不擅自改变已有账号或批量导入语义。手动新增 Go 账号的表单默认并发为 1。

- 限制由原子 pool lease 预约/提交/释放；等待和取消不会造成重复扣 RPM 或泄漏在途数。
- 元数据、额度与出口诊断不算推理次数。
- Go 路由保存为独立副本，概览使用 Go 的有效策略，而不是错误显示全局策略。
- Go 页面隐藏对本池无效的 OpenDesign 钱包回退、忽略目录以及会话忙时溢出选项；被隐藏的原有字段通过设置对象保留，不重置其他池。
- 可在 Go 路由中配置等待、TTL、尝试次数和超时。初验建议并发 1、有界 RPM 和一次上游尝试；这不是官方“安全阈值”。

### 未命中绑定时的“近1小时请求最少”策略

未命中会话不一定是轮询：原有默认 `smart` 综合额度/重置时间等排序；`roundrobin` 才是轮询；`least-used` 比较额度比例和衰减 Token，不是最近一小时的请求计数。

新增可选 `least-requests-1h`（路由设置 → 选号策略，说明为“近1小时请求最少”）。不自动改变现有默认策略、其他池或线上配置。

1. 保持 **原会话绑定 → 缓存亲和 → 新选号策略**。热会话不会为了均衡而悄悄换账号。
2. **先剔除不可用账号，再比较请求数**：禁用、隔离、冷却、政策暂停、无模型权限、已确认额度耗尽，以及24h成功率低于已配置最低健康分的账号均不进入候选集；本策略强制执行健康门槛，不依赖可选 `healthFilter` 开关，其他策略保留原开关语义。会话/缓存命中也不能绕过这些检查，预览与实际选号保持一致；全部不可用时返回错误，不为了均衡强选。Go 任意一个有效额度窗口耗尽即剔除。健康样本不足20或额度未知/过期不等于已确认不健康/耗尽，沿用原未知状态规则，不能据此宣称“已确认有额度”。随后在相同优先级的账号里比较：**近1h已发送次数＋当前待发送预约**。同时来的新请求不会在发送前全挤到一个低计数账号。
3. 负载相同，依次优先在途更少、最后一次新选号更早，再做轮转；不拿历史累计选号数覆盖近1h负载。原有并发/RPM、满载等待和严格 Responses 绑定仍生效。
4. 计数在上游请求头实际发送时提交一次：包含会话命中、流式请求、已发出但返回错误的尝试。一个下游请求若有多个获准上游尝试，每次分别计数。未发送就取消、本地拦截、协议预检、目录/额度/管理测试都不计入。
5. 统计为**当前分钟及之前59个分钟桶**，随时间滚动，不是每个整点清零；边界为分钟精度。它按请求次数而非 Token/金额均衡，不代表官方配额或“安全频率”。
6. 每账号最多60个稀疏桶，复用 `selection-counters.json` 的 version 1 可选字段。与既有计数同样每5秒保存、正常停机刷盘；重启恢复已保存的有效桶，意外退出可能丢失最近一次刷盘后的计数。待发预约不落盘。
7. 旧文件没有时间桶时从新版开始记录，不用历史累计次数伪造最近1h；升级初期不足一小时的历史不会回填。换策略不清空已收集的有效桶。Go 账号列表显示“近1h已发/待发”，请求日志沿用 selector/selectionReason 标识本次是否实际采用该策略。

本地 Mock 浏览器验证：保存 Go 策略后 Zen/Token Harbor 仍为 smart；一个会话累计4次仍在同一账号，另两个新会话优先使用低负载账号，页面/API分别显示4和2；真正重启 Mock 服务后策略和4/2计数恢复、待发为0。自动化另外覆盖缓存亲和优先、80个并发预约、发送幂等、失败/本地拒绝、窗口过期/时钟回拨、旧文件、深复制、无效快照和计数清除后的迟到回调。没有真实付费推理。

**回滚注意**：旧二进制不认识新的策略枚举，若已选择该策略，回滚前先改回旧版支持的策略（如 smart），不要整体恢复旧配置覆盖其他在线写入。旧版可忽略并在写回时丢弃新增的小时桶；按既有部署约定保留必要备份。

## 4. 政策暂停与安全重试

新增 `opencode.goPolicyCooldownSec`，默认 300，范围 1–86400，0 采用默认值。

- 原有明确门禁/abuse 拒绝继续硬性 stop；Go 额外识别明确 `policy_violation`、账号暂停等已知政策信号，普通模型 permission denied 不自动归类为封号。
- 认证/账号政策拒绝暂停该 Go 账号；明确网络 abuse 还暂停使用同一已配置出口或同一预期 IP 的 Go 账号。不会因此影响 Zen/其他池。
- 使用已有可持久化 pool cooldown，不另建一个重启就忘记的熔断器。账号状态显示“政策暂停”，后续请求不能通过同一已知出口换账号继续重试；该账号的目录/额度查询及诊断也不会继续访问上游，需先审核恢复。
- 绑定到政策暂停账号的会话不会悄悄移给另一账号；可在确认问题解决后人工恢复相应账号。
- 流已输出后出现政策错误，同样记录错误并暂停；原 HTTP 200 和流失败分别记录，请求表按失败标红，不重放、不把已发送内容改成另一次生成。
- 既有认证隔离、模型级错误、Retry-After、已发送结果不确定时不跨号重放等边界保留。

分类基于可验证的状态/已知错误信号，不是供应商私有风控的完整复刻；没有“不封号”承诺。

## 5. Go 概览和日志

### 概览

- Go 账号可调度数、当前并发、有效已配置/已学习容量、未限并发账号数。
- Go 专属策略、下游 Key 数、会话/响应链绑定数；不混入 Zen/其他池。
- 每账号三窗口、额度新鲜/未知/耗尽；共享订阅百分比不相加。
- 出口校验状态和政策暂停账号数。
- 请求成功/失败/取消、输入/输出、已报告缓存读取/写入、测量覆盖。
- 会话绑定命中率、缓存偏好命中和实际缓存 token 读取占比分开呈现。
- 平均耗时与有测量的平均首事件时间；不把首事件冒充首个文本 token。
- Go token/缓存写入/时延缺失测量时显示未知；历史数据不编造覆盖率。价格表估算不标成 Go 实际订阅账单。

### 请求日志

在原有记录上增加客户端类型、缓存提示来源、缓存亲和结果、出口校验状态/观测 IP。已有账号、模型、协议、用量、缓存写入、绑定结果、尝试次数和上游请求关联继续保留。可按客户端筛选。

缓存亲和结果包括：`miss`、`hit`、`session-preferred`、`busy-fallback`、`unavailable`、`invalidated`。它们是选择过程，不是假造的上游 cache hit。

### 错误日志

区分 `local`、`upstream`、`transport`：本地容量/参数拦截、出口校验失败、上游响应、传输错误等。保留对应 request ID、账号、模型、上下游状态、规则、暂停和重试信息，支持按来源筛选。流内错误也保留原 HTTP 状态。

原始 session/cache key 和 HMAC 不写进普通日志。可选详细日志继续默认关闭；Go 的会话/缓存标识、metadata 用户会话信息额外脱敏，无法安全投影的正文省略，原生网络请求不受影响。Proxy label 不包含代理凭证。

## 6. 本地验收

自动化覆盖：

- 显式会话与变化/共享 cache hint 冲突，父子任务、调用方隔离，非 Go identity 顺序不变。
- 新会话缓存偏好、忙时回退不抢缓存归属、已有会话满载不借号。
- 原生缓存正文不改写，真实 UA 保留/通用 UA 兜底，详细日志标识脱敏。
- Responses 续传及 checkpoint 后复用同一匿名上游会话。
- IP pin 合并校验、同 IP 共享、漂移阻断、额度/推理同代理、无凭证探测、不扣健康/RPM。
- 政策暂停后不通过共享出口换账号继续请求，流提交后错误不重放，缓存来源变化拒绝迟到旧结果。
- Go 概览隔离、cache coverage 与统计导入导出。
